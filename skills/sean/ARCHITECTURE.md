# Sean 公开版架构

版本：0.2.0-public。仓库名称：sean-skill-oss。安装入口保持 `sean`，与私人版同名，不能混装在同一发现目录。

## 结构与读取流程

当前任务 → 一条主路线 → 相关主题 → 必要时读取公开条目 → 交付结果并接受修正。

五条路线分别完成方案判断、概念探究、伦理取舍、自我反思和观点表达。七份主题文件覆盖目标、理解、证据、伦理、偏好、概览与公开记录读取方法。证据目录仅有转述、教学示例和边界说明。

入口负责选择任务，路线负责推进步骤，主题负责方法与适用条件，公开条目负责记录分类和限制。日常任务不用加载全部条目。普通事实或机械处理不自动加入个人认知解释。

## 隐私设计

从经过筛选的公开文字重新构建文件树，不继承私人仓库的 Git 对象、提交、标签或分支。不得采用先复制完整私人包再删除几行的发布方式。

所有公开条目重新编号。没有精确原话与旧新编号映射，没有私人路径、原消息定位、原始内容哈希或实际人物关系。假设教学例子独立标注，不能声称来自真实经历。

公开偏好由当前使用者自行采用，不自动当作其个人事实。新用户输入只用于当前任务；写回公开包必须是明确的独立维护请求，并再次检查隐私。

## 维护流程

1. 修改与当前任务有关的文件，保留未请求改动。
2. 同步涉及的路线、主题与公开条目，保留类别及适用边界。
3. 检查所有新增文字、链接、代码样例和元数据，避免私人内容回流。
4. 更新根目录清单并运行 `python3 scripts/validate.py`。
5. 逐项试用 `tests/scenarios.json`；结构检查不等于真实模型行为测试。
6. 仅在独立仓库提交。发布前检查将被公开的所有提交、分支、标签和附件，而不只是当前文件树。

## 验证边界

自动检查覆盖显式发布白名单（拒绝额外文件、缓存和意外目录）、文件清单与哈希、JSON 结构、编号唯一性与引用、相对链接、命名、显式危险字段与常见密钥模式。关键词检查不能证明语义上绝无隐私，需要逐文件人工复核。

公开版不继承私人版过去的试用通过结论。宿主自动发现、长期效果、DSH 兼容性与所有真实场景仍需实际测试。
