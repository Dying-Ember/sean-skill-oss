# Sean 公开版架构

版本：0.3.1-public。仓库名称：sean-skill-oss。安装入口保持 `sean`，与私人版同名，不能混装在同一发现目录。

## 结构与读取流程

当前任务 → 一条主路线 → 相关主题 → 必要时读取公开条目 → 交付结果并接受修正。

五条路线分别完成方案判断、概念探究、伦理取舍、自我反思和观点表达。九份主题文件覆盖目标、理解、证据、制度发生、伦理、偏好、判断方式、概览与公开记录读取方法。证据目录仅有转述、教学示例和边界说明。

入口负责选择任务，并先区分精确判断与日常澄清。路线负责推进步骤，主题负责方法与适用条件，公开条目负责记录分类和限制。日常任务不用加载全部条目。普通事实或机械处理不自动加入个人认知解释，也不上升为挑战问题前提。

## 隐私设计

从经过筛选的公开文字重新构建文件树，不继承私人仓库的 Git 对象、提交、标签或分支。不得采用先复制完整私人包再删除几行的发布方式。

所有公开条目重新编号。没有精确原话与旧新编号映射，没有私人路径、原消息定位、原始内容哈希或实际人物关系。假设教学例子独立标注，不能声称来自真实经历。

公开偏好由当前使用者自行采用，不自动当作其个人事实。新用户输入只用于当前任务；写回公开包必须是明确的独立维护请求，并再次检查隐私。

## 维护流程

1. 修改与当前任务有关的文件，保留未请求改动。
2. 同步涉及的路线、主题与公开条目，保留类别及适用边界。
3. 检查所有新增文字、链接、代码样例和元数据，避免私人内容回流。
4. 更新根目录清单并运行 `python3 scripts/validate.py`。
5. 逐项试用 `tests/scenarios.json`；结构检查不等于真实模型行为测试。
6. 仅在独立仓库提交。发布前检查将被公开的所有提交、分支、标签和附件，而不只是当前文件树。

## 判断方式增量

0.3.1 将判断方式写入入口、主题和路线完成条件。精确判断力求接近本人会做的判断或所用逻辑；不足以代替下判断时，指出问题本身的问题，并澄清方向与条件边界。限定范围内可检查层次、口径和前提，但不是每个问题都先攻击前提。思考方式的概括先与既有记录核对，再给有边界的结论。精确判断与日常澄清不可混用。已有专业方法时，专业检查是判断的一部分，不能用类比换薄。方案判断、概念探究、伦理取舍、观点表达和自我反思的完成条件使用同一条日常澄清护栏，避免精确判断误伤事务性请求。

本次只写方法。不新增公开条目，不纳入私人原话、会话逐字记录、可定位的私人情境、工作场所案例或未脱敏身份细节。这些步骤不能写成使用者逐项认领过的准则。

验证本增量时要另行试用，不能只靠结构检查：

1. 使用材料中没有直接出现过的迁移题，避免贴近原材料的开卷或过拟合。
2. 同一迁移题对照使用该方法与不使用该方法的回答。
3. 精确判断题和日常澄清题都要覆盖。精确判断题在层次、口径或条件立不住时先指出，专业问题做专业检查；日常澄清题对准后直接完成，不挑战问题前提。

`tests/scenarios.json` 只规定这些行为边界，不能代替上述迁移对照。

## 验证边界

自动检查覆盖显式发布白名单（拒绝额外文件、缓存和意外目录）、文件清单与哈希、JSON 结构、编号唯一性与引用、相对链接、命名、显式危险字段与常见密钥模式。关键词检查不能证明语义上绝无隐私，需要逐文件人工复核。

公开版不继承私人版过去的试用通过结论。宿主自动发现、长期效果、跨宿主兼容性与所有真实场景仍需实际测试。
