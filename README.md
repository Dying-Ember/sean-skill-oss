# Sean Skill · 公开脱敏版

**保留偏好和问题处理方式，让方法可以分享。**

`sean` 是一套可由文件读取型 Agent 使用的认知参考 skill，覆盖方案判断、概念探究、伦理取舍、自我反思和观点表达。这个版本将私人材料改写为有适用边界的公开转述，不包含私人原话或私人来源索引。

- 仓库：[Dying-Ember/sean-skill-oss](https://github.com/Dying-Ember/sean-skill-oss)，独立公开仓库
- 版本：`0.2.0-public`
- 调用入口：`$sean`
- 安装单元：[`skills/sean/`](skills/sean/) 整个目录
- 运行依赖：能读取本地文本文件的 Agent。验证脚本需要 Python 3.9 或更高版本，只使用标准库。
- 许可证：[MIT](LICENSE)。版权归属为仓库作者的 GitHub 标识 Dying-Ember。

## 保留了什么

保留对用途和目标的校准、具体问题的处理步骤、学习与工具偏好，以及理解、证据、公平和责任等讨论。它不预设固定人格或唯一价值排名，也不将这些偏好默认归给每一位使用者。

家庭信息、健康信息、欲望的具体形式和可识别私人经历不进入公开包。原始选引及消息、路径、时间和来源关系被整体替换，而非只给个别句子打码。详见 [隐私说明](PRIVACY.md)。

## 使用

```text
$sean 比较这两个方案，先对齐目标与限制，再给出推荐、主要代价和改变结论的条件。
```

```text
$sean 我想讨论“按步骤做对”和“理解步骤作用”的区别，继续分析过程、本质与竞争解释。
```

```text
$sean 这个排名处罚方案是否公平？请分开讨论个人表现、统一规则和后果承担。
```

```text
$sean 针对我现在提供的材料找反例与盲点，不要把公开版方法当成我的历史原话。
```

```text
$sean 根据我现在的立场写一段意见草稿。受众、材料与希望促成的事情如下：……
```

普通事实查询、翻译和机械编辑不需要个人认知分析。公开版不提供精确历史引语；要求原话时，Agent 应说明限制，并仅使用当前用户主动提供的材料核对。

## 安装

在本仓库选择 **Code → Download ZIP** 并解压，取出整个 `skills/sean` 目录。在 Codex 中，常用用户目录为 `~/.agents/skills/sean`，Windows 对应 `%USERPROFILE%\.agents\skills\sean`；请以当前宿主实际支持的位置为准。最终应能找到 `sean/SKILL.md`，不要只复制入口。

如果已有私人版 `sean` 或旧名 `pwrm`，先比较差异并备份到 skill 发现目录之外，再安装。不要把新旧文件混合，也不要将私人版本以 backup 名称留在自动发现目录中。安装公开版不会更新或删除私人仓库。

安装后在下一轮输入 `$sean`；宿主未刷新时重启。其他支持读取文件的 Agent 可以这样使用：

```text
请读取 <安装目录>/sean/SKILL.md，按其中路由处理下面的问题。使用公开转述作为方法参考，不把它当作我的原话或默认偏好。
我的问题是：……
```

本包不承诺 DSH 或所有宿主的自动注册。没有经过核实的注册机制时，直接读取文件入口即可，不要猜测安装命令。

## 文件结构

```text
sean-skill-oss/
  README.md

  LICENSE                     # MIT 许可证
  skill-manifest.json          # 19 个 skill 文件的字节数与 SHA-256
  release-manifest.json        # 除自身外的全部发布文件

  tests/scenarios.json         # 行为试用场景，不等同自动模型测试
  skills/sean/
    LICENSE                   # 随安装目录保留的同一 MIT 许可证
    SKILL.md
    ARCHITECTURE.md
    agents/openai.yaml
    routes/                   # 5 条任务路线
    references/               # 7 份主题与使用边界
    evidence/                 # 31 条转述、5 个假设示例、资料边界
```

路线和主题逐步加载，日常任务无需读取全部条目。维护规则见 [架构说明](skills/sean/ARCHITECTURE.md)。

## 验证

先确认安装了 Python 3.9 或更高版本，再在包根目录运行：

```sh
python3 scripts/validate.py
```

检查覆盖：发布文件显式白名单（拒绝额外文件、缓存和意外目录）、skill 清单的数量、字节数与哈希，所有公开记录的类别和限制，条目编号及引用，相对链接，旧证据文件或字段残留，常见密钥模式和部分私人定位模式。该脚本不读取网络，也不收集用户数据。

然后用 [行为场景](tests/scenarios.json) 逐项试用。静态检查通过不等于模型行为、所有宿主自动发现或长期效果已通过验证；关键词扫描也不能代替逐文件隐私复核。
